# Виртуальные маршруты темы

Файл: `inc/virtual-routes.php` (подключается из `functions.php` последним).

Тема отдаёт внутренние страницы, услуги, объекты портфолио и статьи блога из собственных демо-данных
(`inc/demo-data.php`), когда в базе WordPress нет подходящих записей. Реальный опубликованный контент
всегда в приоритете: если в базе появится страница, услуга или проект с тем же адресом, маршрут
уступает и работает обычный шаблон WordPress.

## Маршруты

| Адрес | Шаблон | Данные |
| --- | --- | --- |
| `/services/` | `archive-service.php` | `kitstroy_get_demo_services()` |
| `/services/{slug}/` | `single-service.php` | `kitstroy_find_demo_service_by_slug()` |
| `/portfolio/` | `archive-portfolio.php` | `kitstroy_get_demo_portfolio()` |
| `/portfolio/{slug}/` | `single-portfolio.php` | `kitstroy_find_demo_portfolio_by_slug()` |
| `/blog/` | `page-blog.php` | `kitstroy_get_demo_posts()` |
| `/blog/{slug}/` | `single.php` | `kitstroy_get_demo_posts()` + `kitstroy_get_demo_post_content()` |
| `/about/` | `page-about.php` | текст из `docs/demo-content.md` |
| `/prices/` | `page-prices.php` | `kitstroy_get_default_prices()` |
| `/contacts/` | `page-contacts.php` | `kitstroy_get_contact_data()` |
| `/privacy-policy/` | `page.php` | текст из `docs/privacy-policy.md` |

Слуги берутся из демо-массивов: 8 услуг, 6 проектов, 3 статьи.

## Как это работает

1. `init` — `add_rewrite_rule()` (приоритет `bottom`) для каждого маршрута и версия маршрутов в опции
   `kitstroy_virtual_routes_version`; при несовпадении версии правила сбрасываются автоматически, без
   захода в админку. `flush_rewrite_rules()` также висит на `after_switch_theme`.
2. `parse_request` — путь запроса разбирается вручную, поэтому маршруты работают даже до сброса правил.
   Если в базе есть опубликованный объект с таким адресом, тема ничего не меняет.
3. `pre_get_posts` — основной запрос обнуляется для виртуального маршрута; там же скрываются дефолтная
   запись «Hello world!» и служебная страница «Sample Page».
4. `pre_handle_404` + `template_redirect` (приоритет 5) — запрос собирается заново: подставляются
   синтетические записи, выставляются условные теги (`is_page`, `is_single`, `is_post_type_archive`),
   статус ответа 200.
5. `template_include` — принудительно подключается шаблон маршрута из таблицы выше.
6. `post_link`, `page_link`, `post_type_link`, `get_canonical_url` — постоянные ссылки и canonical
   синтетических записей указывают на адрес маршрута, а не на структуру постоянных ссылок WordPress.

Меню: если в WordPress не назначено меню, вместо `wp_page_menu` выводится собственное меню темы
(`kitstroy_nav_menu_fallback`): Услуги, Портфолио, Цены, О компании, Блог, Контакты.

## Проверено

- Все 50 PHP-файлов темы разобраны PHP-парсером: синтаксических ошибок нет; все вызовы `kitstroy_*`
  имеют определения; дублей функций нет; имена коллбэков во всех `add_action`/`add_filter` существуют.
- Слаги демо-данных сверены с префиксами ссылок в карточках (`/services/`, `/portfolio/`, `/blog/`) —
  расхождений нет; у всех трёх демо-статей есть полный текст; все шаблоны маршрутов есть на диске.
- Инвентаризация ссылок темы (`href`, `get_permalink`, `home_url`, `get_post_type_archive_link`): для
  каждой ссылки есть либо реальный объект WordPress, либо маршрут из таблицы.

## Не проверено

- Живой рендер в браузере и реальные HTTP-статусы (нет PHP и доступа к серверу).
- Поведение вместе с активными плагинами живого сайта (SEO-плагин, CookieAdmin).

## Риски при первой загрузке

- Тема рассчитана на «красивые» постоянные ссылки. Если структура постоянных ссылок в WordPress
  переключена на простую (`?p=123`), виртуальные адреса работать не будут.
- Сброс правил перезаписи выполняется при первом запросе после загрузки файлов и требует права записи
  в таблицу опций.
- На живом сайте активен SEO-плагин (формат `<title>` не совпадает ни с ядром, ни с темой), поэтому
  заголовки и canonical виртуальных страниц формирует он; хелперы темы (`inc/seo.php`) включаются,
  только если плагин отключён.
